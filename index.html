How the internal listener works. The Web Speech API only listens to the microphone — it cannot accept a media stream directly. So capturing system audio means routing that audio back into a microphone input. Two ways:

  1. Speakers → mic (zero install). Choose System / tab audio, click Capture system audio, pick a Chrome tab (not "Entire screen") and tick Share tab audio. Keep Monitor volume audible — your speakers play the tab, the mic hears it, captions appear. Use headphones only if you switch to the cable method.
  2. Virtual cable (fully internal, silent). Install a loopback driver — VB-CABLE (Windows), BlackHole (macOS) or PulseAudio null-sink (Linux). Route the app's output into the cable, then set the Monitor output device above to that cable (or route the source app directly in the OS mixer) and set the OS default input to the same cable. Now the recogniser hears the cable directly — keep the monitor muted so nothing plays out loud.
Auto-detect: recognition starts in your browser language; if nothing parses it silently scans common languages, then switches based on script analysis. Click the blue chip to reset.
